# AURA — Agent-based Understanding and Recovery of Applications

AURA is a nine-agent LLM framework that recovers business rules from
legacy software with **traceability and execution evidence**: every claim
carries a source span, every claim that can run is executed against the
real code, and an evidence **safety gate** keeps contradicted rules out of
generated artefacts.

Full research report: **[REPORT.md](REPORT.md)** (research questions,
framework, benchmark, metrics, experiment results, threats, reproduction).

## Highlights

* **Nine agents, one shared state, one protocol** — RepoMap →
  GrammarHypothesis → ASTMap → RuleInventory → EvidenceReport → BSG →
  ModernizedCode → EquivalenceReport → Documentation, with schema and
  provenance self-checks before every artefact commit.
* **Evidence safety gate** — rules whose contracts are contradicted by
  execution become `blocked_on_human` nodes with counterexamples; the
  Transformer never generates from them. In the safety experiment
  (10 injected false rules per unit) the gate blocks **60/60** false
  rules and leaks **0** blocked nodes into generated code; with the gate
  ablated (A3) every blocked node leaks.
* **Six-unit benchmark, ground truth by construction and by verification**
  — two hand-built legacy dialects (ILG, RPT) plus COBOL, Go, Java and
  legacy-React projects; every rule contract and golden test is executed
  against the real code: **242/242 checks pass**.
* **Real toolchains first, bundled interpreters as fallback** — `go run`,
  `javac`/`java`, `node` when present; deterministic subset interpreters
  (cobolite, gosim, javasim, dsl_interp) otherwise. CI cross-validates
  them against the real compilers.

## Quickstart

```bash
pip install -r requirements.txt        # tree-sitter==0.20.4 pin is required

python bench/scripts/validate_ground_truth.py   # 242 ground-truth checks
python -m pytest tests -q                       # unit tests
python -m aura selftest                          # 9 agents end-to-end (offline)

# full offline experiment matrix (A0-A3, S1 safety, B1-B3 baselines)
python experiments/run_matrix.py --provider offline --out results
python experiments/aggregate.py --results results
```

Real-model evaluation (OpenAI, est. USD 1-3 for the full matrix):

```bash
export OPENAI_API_KEY=sk-...           # never committed; see .env.example
./experiments/run_openai.sh
```

or set the `OPENAI_API_KEY` repository secret and dispatch the
**AURA evaluation** GitHub Actions workflow (`.github/workflows/
aura-eval.yml`), which runs the whole protocol on `ubuntu-latest` with
Go, Temurin 21 and Node installed and uploads `results/` as artefacts.

## Layout

```
aura/        framework: shared state + protocol, LLM providers,
             skills (lexers, grammar inference, input generation,
             spec-driven codegen, execution adapters, sandbox)
  agents/    the nine agents
  eval/      metrics + run scoring (capture, BLEU-4, BERTScore proxy,
             recall, traceability, BER, safety gate, Wilcoxon)
bench/       benchmark: dialects/ + projects/, ground-truth scripts
experiments/ matrix runners, baselines, aggregation, run_openai.sh
tests/       pytest suite
results/     committed offline experiment matrix + summary
docs/        reference sources
REPORT.md    research report
```

## Reproducing the report numbers

Every table in REPORT.md is regenerated by the commands in its §10 and
the committed `results/summary.md`. The OpenAI matrix (REPORT §7) needs
API access and uploads `results-openai/` from CI.
